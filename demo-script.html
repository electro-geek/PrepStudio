🎙 Your Answer — Q1
Alex asks →
"Can you explain what REST is and describe the key principles that make an API RESTful?"
Your answer
"REST stands for Representational State Transfer. The key principles are: statelessness — each request contains all the info the server needs, no session stored between calls. A uniform interface using HTTP methods — GET for reading, POST for creating, PUT or PATCH for updating, DELETE for removing. Resources are identified by URLs. So instead of slash-getUser, a REST API says GET slash users slash 1."
3:00 – 3:20
🎙 Your Answer — Q2
Alex asks →
"What is the difference between PUT and PATCH, and what HTTP status codes would you use for a successful creation versus a bad request?"
Your answer
"PUT replaces the entire resource. PATCH is for partial updates — I only send the fields I want to change. On status codes: 201 Created for a successful POST, 200 OK for a successful GET or PUT, 204 No Content for a successful DELETE. For errors — 400 for invalid data, 401 when there's no auth token, 403 when the token is valid but lacks permission, and 404 when the resource doesn't exist."
